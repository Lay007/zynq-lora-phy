# Регрессия итоговой ToA на полных пакетах

[English version](../joint-toa-regression.md)

`tools/joint_packet_regression.py` подаёт полные пакеты на RTL приёмника SF7/L8:
1 млн отсчётов/с, чередование 62/63 тактов PL на отсчёт. Проверяются итоговая
метка coarse/Q12, CRC, точное совпадение payload и запас времени до заголовка.
Это моделирование, а не измерение аппаратной точности, RF-смещения или
синхронизации приёмников.

## Запуск

Нужны Linux или WSL, Verilator, компилятор C++ и зависимости проекта
(`python -m pip install -e ".[dev]"`). Из корня репозитория:

```sh
python tools/joint_packet_regression.py --suite baseline --out build/joint-baseline
python tools/joint_packet_regression.py --suite timing --out build/joint-timing
```

Каталог вывода должен быть новым или пустым. Предыдущие результаты не
перезаписываются. `--jobs` задаёт параллелизм сборки, `--timeout` ограничивает
время моделирования одного сценария в секундах, по умолчанию 300.
Оба набора включены в матрицу `joint-full-packet` в `rtl-ci.yml`.

## Сигнал и ожидаемое время

- `baseline`: исходные 17 сценариев без шума. Квантованные IQ побитово
  сохранены. Проверяются оба знака CFO 418/1000/1500 Гц, дробные задержки,
  фазы прихода у границ символов и преамбулы из 8/12 символов.
- `timing`: 16 дополнительных сценариев. Четыре сочетания фазы, CFO, длины
  преамбулы и дробной задержки проходят с SFO -20/+20 ppm, без шума и с AWGN
  при SNR 10 dB в полосе 125 кГц. Seed фиксирован. Это небольшая
  детерминированная матрица, не статистическая PER-кампания.

Дробная задержка задаётся исходным FFT-сдвигом с нулевыми защитными участками.
Затем весь поток пересчитывается линейной интерполяцией:
`y[n] = x[n * (1 + sfo_ppm/1e6)]`. Знак совпадает с MATLAB-моделью канала:
положительный SFO сдвигает события раньше. Интерполяция является частью модели
воздействия и может менять форму сигнала. CFO добавляется после неё в координатах
приёмника. Комплексный белый шум занимает всю полосу дискретизации; его дисперсия
равна `Fs/BW * 10^(-SNR/10)` при единичной мощности пакета и не зависит от длины
защитных участков. Перед округлением в int16 сигнал умножается на 400;
выход за диапазон вызывает ошибку.

Для `S=1024`, `lead=2048+phase`, дробной задержки `f`, длины преамбулы `P`
и отношения частот `r=1+sfo_ppm/1e6`:

```text
ToA = (lead + f + (P-8)*S) / r
header_start = (lead + f + (P+4.25)*S) / r
```

Начало ToA соответствует первому из оставленных восьми chirp преамбулы.
Эти координаты получены из входного сигнала, без использования решений
детектора, декодированного payload или подгонки времени. Дробная задержка и
SFO учитываются также в координате заголовка; ранее использовалась несдвинутая
координата заголовка.

## Критерии и отчёты

Исходные пороги сохранены: абсолютная ошибка ToA **строго меньше 0,5 отсчёта**,
запас до заголовка **строго больше 96 отсчётов**. Дополнительно требуется ровно
одна детекция, одна метка и одно завершение совместного поиска, дробь Q12
в пределах +/-0,5 отсчёта, полная трасса, успешный выход симулятора,
корректный payload CRC и точное совпадение переданных байтов.

Ошибка или таймаут одного сценария сохраняются в отчёте; остальные сценарии
всё равно выполняются. Если хотя бы один не прошёл, код возврата ненулевой.
Сбой инфраструктуры, например сборки, останавливает запуск; начальная сводка
сохраняет число запланированных и ещё не выполненных сценариев.

- `results.json`: результаты каждого сценария, исходная метка, ожидаемые
  координаты, причины ошибок, задержки и хеши IQ/логов;
- `summary.json`: числа запланированных, выполненных и отсутствующих сценариев,
  пропуски детекции/меток, CRC, смещение ToA, RMSE, абсолютные p95/p99,
  максимум и число выбросов;
- `provenance.json`: матрица сценариев, версии инструментов, хеши RTL, ROM,
  генератора сигнала, декодера и кода регрессии;
- входные `.hex`, трассы `.log` и `build.log`.

Статистика включает все однозначные метки, в том числе при ошибке CRC и при
выбросах. Отсутствующие и дублированные метки считаются отдельно, нулевая
ошибка им не присваивается. Смещение и дрейф не вычитаются. Процентили
описывают только проверенные сценарии, без утверждений о генеральной
совокупности. CI сохраняет JSON и логи, точные IQ остаются в локальном каталоге.

Python-тесты проверяют учёт ошибок, побитовую сохранность исходных IQ, знак
SFO, координаты событий и нормировку шума. Полные RTL-прогоны выполняются
отдельно.
