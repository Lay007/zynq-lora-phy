# Эталонный передатчик Heltec WiFi LoRa 32 V4 + SX1262

Прошивка реализует тот же serial-протокол, что и передатчик LR1121: `show`,
`set ...`, `payload`, `send`, `start` и `stop`. После загрузки передатчик всегда
остановлен. BOOT является только аварийной остановкой и не может включить RF.

Версия 0.2.0 пассивно определяет ревизию до включения FEM. На V4.3 GPIO5/CTX
имеет внешний pulldown 10 кОм, а на V4.2 GPIO5 не подключён. Поэтому внутренняя
подтяжка ESP32-S3 даёт 0/32 HIGH для V4.3 и 32/32 для V4.2. Смешанный результат
считается `unknown`: команды `send` и `start` блокируются.

Для V4.2 DIO2 управляет GC1109 CTX, а GPIO46 удерживает CPS в нуле — это
transmit bypass. Для V4.3 GPIO5 управляет KCT8103L CTX, DIO2 — CPS; также
выбирается bypass. Внешний PA не включается, настройка SX1262 ограничена
диапазоном −9…0 dBm, принимаемым используемым API SX1262.

Проверенная плата на COM10 имеет MAC `10:BD:A3:5A:57:90`. Её полный заводской
образ 16 MiB сохранён до прошивки:

```text
<backups>/20260802T200300-heltec-wifi-lora32-v4-sx1262/flash-full-16MiB.bin
SHA-256 A23B73E914815044601FE549FB8C2BC8DF8A5F9701EF5A194271C83130E3C28E
```

Сборка и загрузка:

```powershell
cd firmware/heltec-v4-sx1262-tx
pio run
pio run --target upload --upload-port COM10
```

Безопасная проверка, не создающая радиопередачу:

```text
version
show
help
stop
```

Перед первым пакетом команда `show` должна одновременно сообщать
`running=no`, конкретную `board_revision`, соответствующий `fem=...-bypass` и
однозначный `revision_probe`.

На подключённой плате измерено `revision_probe=0/32`, поэтому она определена
как V4.3 с KCT8103L. Прошивка 0.2.0 проверена передачей 70 пакетов в 27 режимах
на ZynqSDR: все подтверждённые операции завершились `state=0`, после серии
передатчик остановлен (`running=no`). Описание и ограничения измерения приведены
в [отчёте о серии](../../docs/ru/hardware-sweep-2026-08-03-heltec-v43.md).
